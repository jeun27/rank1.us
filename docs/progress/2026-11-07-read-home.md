# Onboarding v2 DP1: readHome (data-pipeline, branch feat/read-home)

Spec: share/ux-plan/onboarding-welcome/README.md §4–§5 (founder-approved O1, 2026-11-07).

- `src/lib/onboarding/site-profile.ts`: `profileFromHtml(html)` (pure) and `readHome(domain)` (robots + home page only, through the shared guarded fetcher; never throws). Returns `SiteProfile` (`types.ts`, extends `SiteRead`; the old fields are kept, `readSite` is unchanged).
- Order per field: JSON-LD (arrays and `@graph` flattened, broken blocks skipped) → meta/og (`og:site_name`, `geo.placename`/`geo.region`) → the title/H1/description. Source tags: schema = JSON-LD, meta = meta tags, title = title/H1/description/page body (also the first `tel:` link).
- Vertical: the §4 @type table. A Product or SoftwareApplication node sets the vertical but never the business name. Without a mapped type, a whole-word keyword match over the title + H1 + description (most hits wins, ties = list order). The keyword lists are mine (§4 gives only the rule).
- Category: the type's label ("plumber", "day spa") or the matched keyword. None for saas/dtc, because "best software software" would read badly; the user picks from the select.
- Cuisine: restaurant (or undetected vertical) only. `servesCuisine` is mapped onto CUISINES, then `matchCuisine` runs over the home text. No /menu fetch (fetch budget: home + ≤1 sitemap, which DP2 uses).
- No city default anywhere.
- Fixtures: tests/fixtures/sites/*.html (8 sites, prettier-ignored so they stay raw). No network in tests.
